## Highlights

**v0.0.8 → v0.0.9** · 5 commits (1 Android-side, shipped as companion 1.4.2)

A scheduled re-patch with the same app and patches version no longer makes phones prompt for an install. A patch-guard regression on an automatic APKMirror variant now tries the next variant, so a lite build that regressed is replaced by the normal build (this fixes Gboard picking the lite build). The browser image build is repaired by pinning playwright 1.64.0. **Images: `jhangyu/relume-app:0.0.9` and `jhangyu/relume-browser:0.0.9`.**

### 🛠 Fixed & Improved

**Server and Web UI**
- A scheduled re-patch makes a new build job and a new APK sha256, and the install plan used to treat that as a new build. Install now happens only when there is no install record, or the record is another job and the version code, version name or patches version differs. A version-code or signer drift still gives install, otherwise the app is up to date.
- A matching reported APK sha256 is kept as an install record, so a later re-patch can still tell which build the phone holds. The patches version is stored on that row.
- ADB up-to-date rows name the build the phone holds, not the newest artifact.
- A patch-guard regression verdict on an automatic APKMirror variant rejects that variant like the earlier verdict does, so the next variant (the normal build) is tried. Builds without an automatic variant still fail the job.
- The browser image pins playwright 1.64.0, because 1.65 removed the module that cloakbrowser 0.6.5 imports.

**Android app** (companion 1.4.2)
- A declined background build is remembered by app, app version, patches version and tag, not by the APK sha256, so a re-patch of the same versions is not asked again.

### ⚙️ Internal / Build

- Schema migration 023 stores the patches version on the install record instead of reading it through the build job.
- The companion APK asset is named `relume-<version>-universal.apk`.

### 📦 Install / Upgrade

- **Server:** pull `jhangyu/relume-app:0.0.9` and `jhangyu/relume-browser:0.0.9` (or `latest`) and redeploy the Portainer stack. The database migrates itself.
- **Android:** install companion 1.4.2 over 1.4.1 to stop the repeated prompt on the phone.
- **Known limit:** a rebuild with changed settings but unchanged versions no longer reaches phones.
